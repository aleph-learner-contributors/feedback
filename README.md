# ALEPH Learner Contributors

ALEPH 학습 과제와 학습 경험을 함께 살펴보고, 질문과 개선 아이디어를 기록하는 공개 공간입니다. GitHub의 Issue와 Project를 사용해 협업하는 방법도 천천히 연습합니다.

> 이 저장소는 ALEPH의 소스 코드나 과제 답안을 올리는 곳이 아닙니다. Issue에 제안을 남기는 것이 실제 반영을 보장하지는 않으며, 담당자가 내용을 확인하고 검토합니다.

## 처음 참여할 때

1. [Issues](../../issues)에서 비슷한 내용이 이미 있는지 먼저 찾아봅니다.
2. 없다면 새 Issue를 열고, 제목에 어떤 과제나 상황인지 간단히 적습니다.
3. 무엇을 하려 했는지, 어떤 일이 있었는지, 어떤 점이 궁금하거나 개선되면 좋겠는지 씁니다.
4. 댓글로 질문에 답하거나 추가 정보를 보탭니다. 담당자가 상태를 바꾸면 진행 상황을 확인합니다.

처음에는 Issue와 댓글만 사용합니다. Pull Request(PR), 코드 변경, Merge는 나중에 별도로 안내할 때 시작합니다.

## Issue를 쓸 때

- 한 Issue에는 한 가지 질문이나 제안을 담아주세요.
- 이미 확인된 사실과 원하는 변화, 아직 모르는 점을 구분해서 써주세요.
- 버그라면 가능할 때 재현 순서, 기대한 결과, 실제 결과를 적어주세요.
- 기능 제안이라면 누구에게 어떤 상황에서 도움이 되는지 설명해주세요.
- 사람을 탓하기보다 문제와 경험을 중심으로 정중하게 이야기해주세요.
- 비슷한 Issue가 있으면 새로 만들기보다 댓글로 내용을 보태주세요.

## 공개 공간에서 지켜주세요

이 저장소와 Issue, 댓글은 인터넷에 공개됩니다. 다음 내용은 올리지 마세요.

- 본인이나 다른 사람의 전화번호, 이메일 등 개인정보
- 비밀번호, 토큰, API 키, 인증 코드
- 비공개 과제 링크·자료, 정답, 제출물, 다른 사람의 작업물
- 허가받지 않은 화면 캡처나 민감한 운영·보안 정보

확신이 없으면 공개 Issue에 올리기 전에 강사에게 먼저 물어보세요. 실수로 민감한 정보를 올렸다면 댓글로 다시 퍼뜨리지 말고 즉시 강사에게 알려주세요.

## 라벨과 진행 상태

라벨은 Issue의 종류와 주제를 구분하는 표식입니다. Project 보드는 어떤 제안이 접수되었고 검토 중인지 한눈에 보는 목록입니다. 처음에는 간단히 쓰고, 익숙해지면 함께 개선합니다.

## 참여 원칙

서로의 아이디어를 존중하고, 제안에는 맥락과 이유를 덧붙입니다. 질문이나 비판은 환영하지만 개인을 공격하거나 몰아붙이지 않습니다. 누구나 배우는 중이며, 작은 발견도 다음 학습자를 도울 수 있습니다.
